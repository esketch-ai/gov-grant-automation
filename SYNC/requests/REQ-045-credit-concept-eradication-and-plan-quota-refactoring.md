# REQ-045: 게임 머니식 '크레딧·코인' 용어 전면 퇴출 및 '월간 플랜 생성 한도' 체계 개편

- **요청 일시**: 2026-10-28
- **발신**: `GCWA` (총괄 아키텍트 / PM)
- **수신**: `QCWA` (개발 전담 워크스페이스: 박준호 CPO, 최은정 UI/UX, 이승엽 BM엔진, 정민재 DB, 김도윤 연동)
- **참조 및 검수**: `QQAQC` (검수 전담 워크스페이스: 한지훈)
- **우선순위**: CRITICAL (사용자 비즈니스 본질 왜곡 피드백)

---

## 1. 배경 및 문제 진단
사용자 긴급 지적: **"우리가 크레딧을 발행해? 왜 있는거야?"**
- 당사는 통화나 전자화폐, 코인을 발행하는 게임사/핀테크 기업이 아니며, 정부지원사업 맞춤형 솔루션을 제공하는 B2B 플랫폼임.
- 초기 프로토타입 단계에서 LLM API 호출 통제를 위해 해외 AI 서비스의 "API Credit" 개념을 여과 없이 차용하여 화면에 `잔여 크레딧 350회`, `fa-coins`(동전 아이콘), `크레딧 즉시 충전` 등이 부적절하게 노출됨.
- B2B 정부과제 솔루션의 격에 맞도록, 소비자 오해를 유발하는 **'크레딧/코인 충전' 용어를 프론트엔드 전반에서 영구 퇴출**하고, **'구독 멤버십 플랜(Standard/Growth 등) 및 월간 AI 사업계획서 생성 한도(횟수)'** 체계로 정제함.

---

## 2. 세부 개발 요구사항 (for QCWA)

### 2.1 UI/UX 용어 및 아이콘 전면 개편 (최은정 UI/UX)
1. **`src/web/templates/biz_dashboard.html`**:
   - Hero 우측 위젯:
     - `잔여 크레딧` ➔ `이번 달 생성 한도` (또는 `월간 생성 한도`)
     - `fa-coins` 아이콘 제거 ➔ `fa-bolt` 또는 `fa-file-signature` 적용
     - `크레딧 충전` 버튼 ➔ `플랜 한도 관리` (또는 `한도 충전/확장`)
   - 하단 멤버십 안내 카드 (line 255~275):
     - `크레딧 충전 및 요금제 혜택 안내` ➔ `구독 멤버십 플랜 및 AI 생성 한도 관리`
     - `fa-coins` 아이콘 제거 ➔ `fa-award` 또는 `fa-layer-group` 적용
     - `현재 잔여 크레딧` ➔ `이번 달 잔여 생성 한도`
     - `크레딧 즉시 충전` 버튼 ➔ `생성 한도 확장` (또는 `이용권 충전`)
   - 토스트 메시지 (line 347):
     - `'크레딧 300회가 정상 충전되었습니다.'` ➔ `'월간 AI 계획서 생성 한도 300회가 정상 충전되었습니다.'`
2. **`src/web/templates/admin_platform.html`**:
   - 관리자 관제 화면 내 `잔여 크레딧` 또는 `잔여: {{ ... }}회` 라벨을 `월간 생성 잔여: {{ ... }}회`로 정제.
3. **`src/web/app.py`**:
   - 엔드포인트 docstring 및 응답 설명에서 '크레딧' 용어를 '생성 한도(quota)'로 순화.

### 2.2 시스템 호환성 및 기존 계약 보존 (박준호 CPO, 정민재 DB)
- 기존 DB 스키마(`credit_balance`, `credit_ledger`) 및 테스트 코드와의 하위 호환성을 위해 백엔드 내부 모델명/변수명은 유지하되, 사용자 및 관리자에게 보이는 레이블은 **100% '생성 한도 / 월간 이용 횟수'**로 일원화.
